Transaction completion gate

Test real worker termination before takeover; reject mismatched receipts and corrupt recovery bytes; bound both worker and recovery hangs; require a durable outcome or explicit unresolved result. Journal fault cases establish ordering, while actual process tests establish process lifetime. Keep both positive and negative cases. Same-id replay must not repeat effects; another target with that id must be refused.

Maintaining test quality

Use isolated identities, temporary directories and owned processes. Clean on failure. Preserve the first failure when retrying; never delete assertions, silently skip a platform or report model tests as service acceptance. Fixed v1 samples protect disk compatibility without retaining another implementation. Run only affected checks during iteration and all required gates for a release.

cargo run --locked --release --bin k-harness -- sim --start-seed 1 --seeds 50000

The nightly workflow retains failing-seed corpora for replay. Changes to phases, intent ordering or effects also require reviewing the Lean projection.

Platform and product acceptance

CI requires Linux, macOS and Windows checks, including native examples and packaged-source builds. Lean runs separately. Passing K CI does not certify every service manager or target architecture.

For each product target, verify clean installation, repeated installation, owner refusal, live upgrade, bad-candidate rollback, offline recovery and independence from the resident's service boundary. Verify workload/data preservation, enrollment and cloud reconnection when promised. Elephant's launchd/systemd tests are product-level evidence, not K's generic controller contract.

Physical power loss and product reboot hooks require separate evidence. POSIX directory synchronization and Windows image semantics are documented in the reference; Windows directory sync does not provide the same durability guarantee.
